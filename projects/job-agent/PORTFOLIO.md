# Job Agent 作品集案例

补充页面稿见：`PORTFOLIO_CASE_STUDY.md`。这份文件更适合直接复制到作品集页面里，包含页面结构、截图清单、简历 bullet 和 30 秒/2 分钟面试介绍。

## 项目一句话

`Job Agent` 是一个本地运行的求职场景 AI Agent。它可以读取岗位 JD 和简历，自动提取岗位要求、识别简历亮点、计算匹配度、给出证据句、生成简历补强建议和面试准备问题。

这个项目的目标不是做一个简单的 ChatGPT prompt，而是完整走一遍 AI 应用从需求定义、输入处理、Agent 编排、规则匹配、报告输出、评测修正到作品集包装的流程。

## 为什么做这个项目

求职和职业转型是一个真实、高频、容易解释价值的场景。用户通常会遇到几个问题：

- 不知道自己的简历和目标岗位到底匹不匹配。
- 不知道 JD 里真正重要的要求是什么。
- 不知道简历应该优先补哪几段经历。
- 不知道面试前应该围绕哪些短板准备故事。

所以这个项目选择了一个很小但完整的闭环：

```text
岗位 JD + 简历
    ↓
岗位要求提取
    ↓
简历亮点提取
    ↓
匹配分析和证据定位
    ↓
可直接改写的简历 bullet + 面试问题
    ↓
Markdown 报告 + JSON 结构化结果
```

## 当前已经实现的能力

- 支持读取 `.txt`、`.md`、`.pdf` 和常见图片格式。
- 支持 macOS 文本包，例如 Finder 里看似 `.txt`、实际包含 `TXT.rtf` 的情况。
- 支持文本型 PDF 简历解析。
- 支持对 PDF 简历常见断行做基础合并，减少证据句被截断的问题。
- 支持图片 OCR，中文截图默认使用 `chi_sim+eng`，并补充 OCR 空格清洗。
- 支持中文 JD 解析，能识别“岗位职责”“任职要求”等章节。
- 支持中文能力词匹配，例如智能化产品、AI、大模型、产品规划、技术协作、用户需求、市场洞察。
- 支持过滤简历中的电话、邮箱等联系方式，避免把隐私信息当成匹配证据。
- 支持根据匹配结果生成结构化简历改写建议，包括目标要求、当前证据、重组后的推荐 bullet 和改写理由。
- 输出中文口语化 Markdown 报告。
- Web UI 展示层会把内置英文样例转为中文，并使用高对比度文字提升可读性。
- 输出结构化 JSON，方便后续接 Web 页面或评测系统。
- 提供本地 Streamlit Web UI，支持样例运行、真实样例运行和上传文件分析。
- 使用 `.gitignore` 排除虚拟环境、运行产物和真实个人样例，避免作品集泄露隐私或混入临时文件。
- 内置高匹配、中匹配、低匹配三组评测样例。
- 自动化测试覆盖输入读取、JD 解析、匹配引擎、Agent 主流程、Web UI 辅助逻辑和评测流程。

## Agent 工作流

项目里的 Agent 编排层在 `app/agents/job_application_agent.py`。

它的职责不是亲自完成每一个细节，而是把多个工具和服务串成一个完整任务：

```text
1. 读取 JD 和简历
2. 解析岗位标题和岗位要求
3. 提取简历中的相关经历
4. 计算每条岗位要求是否有简历证据支持
5. 生成匹配分、缺口、简历 bullet 改写建议和面试问题
6. 生成 Markdown 报告
7. 导出 JSON 结构化结果
8. 通过 Web UI 展示和下载结果
```

这个设计体现了 AI Agent 的基本思想：围绕一个目标，把任务拆成多个步骤，并调用不同工具完成每一步。

## 关键模块设计

### 输入层

相关文件：

- `app/utils/input_reader.py`
- `app/utils/file_io.py`

输入层解决的是真实用户数据不标准的问题。用户可能上传纯文本、PDF 简历、JD 截图，也可能在 macOS 上保存出一个看起来像 `.txt`、实际是目录的文本包。

项目没有假设用户一定会提供完美文本，而是把输入格式判断、文件校验、PDF 提取、OCR 入口和错误提示集中在输入层。

### Agent 编排层

相关文件：

- `app/agents/job_application_agent.py`

这一层负责主流程编排。它不关心 PDF 怎么解析，也不关心匹配分怎么计算，而是负责让所有模块按正确顺序协作。

这是项目从普通脚本变成 Agent 工作流的关键。

### 解析层

相关文件：

- `app/services/jd_parser.py`
- `app/services/resume_parser.py`

JD 解析器负责从岗位文本里提取核心要求。简历解析器负责从简历文本里挑出更可能有价值的经历，例如带有 AI、产品、数据、协作、结果数字的句子。

当前解析仍然是规则版本，但已经针对中文 JD 做了增强。

### 匹配层

相关文件：

- `app/services/match_engine.py`
- `app/models.py`

匹配层是项目的核心。它不是只做简单关键词重叠，而是维护了一组中英文能力词组。

例如：

- `智能化 / AI / 大模型 / 模型 / 自动化`
- `产品规划 / 产品设计 / 0-1 / 产品定义`
- `技术团队 / 研发 / 协同 / 推动落地`
- `用户需求 / 调研 / 产品特性`
- `市场洞察 / 市场趋势 / 产品定位 / 策略`

匹配结果不仅包含分数，还包含每条岗位要求对应的最佳或最接近简历证据。

### 输出层

相关文件：

- `app/services/resume_rewriter.py`
- `app/services/report_generator.py`
- `app/services/result_exporter.py`
- `web_app.py`

输出层生成两类结果：

- Markdown：给人阅读，适合查看、演示、放作品集。
- JSON：给程序读取，适合评测、Web UI、后续数据分析。

其中 `resume_rewriter.py` 会把匹配结果转成更具体的简历改写建议，并尝试按动作、场景、方法和结果重新组织表达。Markdown 报告已经改成中文口语化表达，避免像工程日志。

`web_app.py` 是展示层，负责上传文件、调用 Agent、分区展示匹配分、证据句、简历改写和面试问题。它没有重写核心逻辑，而是复用已经通过测试的 `JobApplicationAgent`。

### 评测层

相关文件：

- `app/evaluation.py`
- `app/evaluate.py`
- `data/eval_cases/`
- `tests/`

项目内置三组评测样例：

```text
high_match   预期高匹配
medium_match 预期中匹配
low_match    预期低匹配
```

当前评测结果：

```text
high_match: 82, PASS
medium_match: 55, PASS
low_match: 9, PASS
```

评测层的意义是：每次改匹配规则、中文词库或报告逻辑后，都可以快速检查是否破坏了已有表现。

## 真实数据迭代记录

在真实 JD 和 PDF 简历测试中，项目暴露出几个典型问题：

1. 用户的 JD 文档在 macOS 上不是普通 `.txt`，而是包含 `TXT.rtf` 的文本包。
2. PDF 简历可以读取，但部分句子被截断，影响证据句完整性。
3. 初始匹配规则偏英文，中文 JD 和中文简历匹配分只有 `18/100`。
4. 报告一开始中英文混杂，阅读体验差。
5. PDF 页眉里的电话、邮箱等个人信息会被误当成简历亮点。
6. 多条简历句子分数接近时，证据句偶尔会选到不够直接的经历。

对应迭代：

- 增加 macOS 文本包读取能力。
- 增加 PDF 和 OCR 输入适配。
- 报告全部改成中文口语化表达。
- 增加中文 JD 章节识别。
- 增加中文能力词组匹配。
- 增加 PDF 简历断行合并，让长经历更完整地进入匹配流程。
- 增加联系方式过滤，避免隐私信息进入报告。
- 增加证据选择的并列分处理，优先选择更直接命中 JD 原词的简历句子。
- 增加结构化简历改写建议，把“补强方向”升级成“当前依据 + 推荐写法 + 改写理由”。
- 用评测集保证改动没有破坏英文样例。

真实数据多轮迭代后，中文岗位的匹配分从 `18/100` 提升到 `95/100`，并能为 6 条岗位要求定位对应简历证据。

```text
已匹配要求：6 条
```

```text
能对上：负责智能化产品的规划与设计，确保产品满足G端市场需求
```


## 项目亮点

- 不是单次 prompt，而是完整 Agent 工作流。
- 支持真实文件输入，包括 PDF 简历和图片 OCR 入口。
- 同时输出人读的 Markdown 和机器读的 JSON。
- 有可解释匹配结果，每条 JD 要求都能看到对应证据句。
- 能生成结构化简历 bullet 改写建议，并区分“原始证据”和“改写后的推荐写法”。
- 有本地 Web UI，能让非技术用户直接试用和理解结果。
- 有评测集和自动化测试，支持持续迭代。
- 真实使用中发现问题，并完成输入层、输出层、中文匹配层的多轮修正。
- 成本可控，默认 `mock` 模式无需 API Key。

## 当前局限

- PDF 文本提取已经支持基础断行合并，但复杂排版 PDF 仍可能需要更强的清洗策略。
- 中文 OCR 已在代码层默认使用 `chi_sim+eng`，本机已补齐 `chi_sim` 语言包并通过临时中文截图 smoke；真实识别仍受截图清晰度影响。
- 当前匹配机制仍是规则增强版，不是真正深度语义理解。
- 简历 bullet 改写目前仍是规则生成，复杂经历的表达质量后续可以接入 LLM 继续提升。
- Web UI 目前是本地演示版，上传入口和按钮已做人工检查，后续整理作品集截图时可顺手确认下载和报告展示；还没有用户登录、历史记录或部署到公网。
