# job-agent Architecture

## 一句话

本地运行的 Python 求职匹配 AI Agent，包含 CLI、Streamlit Web UI、PDF/OCR 输入、规则匹配、简历 bullet 改写、Markdown/JSON 输出和评测集。

## 顶层结构

- `app/main.py`: CLI entrypoint for local Agent workflow.
- `app/agents/job_application_agent.py`: orchestration layer that reads inputs, parses JD/resume, matches, rewrites, and exports.
- `app/services/`: domain services for parsing, matching, LLM access, report generation, result export, and resume rewriting.
- `app/utils/`: file IO, input extraction, PDF/OCR adapters, and text cleaning helpers.
- `app/models.py`: dataclass schemas for workflow result, match evidence, interview questions, and resume suggestions.
- `web_app.py`: Streamlit presentation layer for uploads, sample runs, result tabs, and downloads.
- `tests/`: standard-library unittest regression suite.
- `data/eval_cases/`: high/medium/low scoring regression fixtures.
- `outputs/`: generated Markdown/JSON/evaluation/Web artifacts, not source.
- `docs/` and `.harness/`: harness documentation and task-control artifacts generated by bootstrap.

## 领域与边界

- Web UI must call `JobApplicationAgent`; it must not duplicate JD parsing, resume parsing, matching, or rewriting logic.
- Input extraction belongs in `app/utils/input_reader.py`; service layers should receive text or structured values.
- LLM/network calls must stay behind `LLMService` and respect mock mode, timeouts, and API-key boundaries.
- Generated reports and evaluations belong under `outputs/`; they are runtime artifacts, not source-of-truth code.
- Private real inputs under `data/my_*` are local test data and must not be committed or used in public docs without anonymization.
- Behavior-changing tasks require unit/evaluation checks plus runtime or interaction verification when UI/CLI behavior changes.

## 禁止事项

- Do not commit `.env`, `.venv/`, `outputs/`, Python caches, or private `data/my_*` files.
- Do not put API keys, resumes, phone numbers, emails, or private JD data into task files or public docs.
- Do not treat build/compile success as behavior proof for Agent, CLI, OCR/PDF, or Web UI changes.
- Do not edit generated runtime outputs to fake successful behavior.
- Do not enable live LLM mode without explicit user confirmation and cost/secret awareness.

## 核心命令图

- .venv/bin/python -m unittest discover -s tests：README.md Run the baseline tests
- .venv/bin/python -m app.evaluate --manifest data/eval_cases/manifest.json --output-dir outputs/evaluations：README.md Run the evaluation suite
- .venv/bin/python -m app.main --jd data/sample_jd.txt --resume data/sample_resume.txt --output outputs/report.md --json-output outputs/report.json：README.md Quick start
- .venv/bin/streamlit run web_app.py：README.md and WEB_DEMO.md local Web UI launch command

## Harness 作用点

- 用 `.harness/tasks/<YYYY-MM-DD>/<type>/<short-slug>/` 承载跨阶段共享上下文。
- 用 `.harness/environment.yaml` 记录运行、调试、Streamlit 前端入口、视口和 MCP Playwright 能力。
- 用 `.harness/workspace-map.yaml` 记录跨项目命令图和相关项目边界。
- 用项目级 skill 做对话式需求入口。
- 用项目原生传感器证明修改结果。
- 用 git 任务分支和阶段性 commit 保留代码演进边界。
