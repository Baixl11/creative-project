# 问题拆解

## P0：输出可信度与隐私

1. 简历改写模板会把“参与”升级为“主导”，并注入 G 端、0-1 等原文不存在的经历。
2. 简历解析无有效亮点时回退到前六行，可能把手机号和邮箱重新送入报告。
3. Web 上传和报告写入 `outputs/web`，未设置删除生命周期。

## P1：核心结果正确性

1. 关键词同义词组过宽且可重复计数，弱相关文本能得到高匹配分。
2. JD 的忽略章节只忽略标题，福利章节正文会重新进入需求列表。
3. 评测有失败用例时进程仍返回成功状态。
4. LLM 实时调用失败后虽使用 mock 内容，但运行模式仍标成 live API；非法 JSON 暴露底层异常。
5. 非 UTF-8 文本输入暴露解码异常，而不是统一输入错误。

## P2：Web 状态与项目可维护性

1. Streamlit rerun 依赖持久文件路径，不能在清理临时文件后继续下载。
2. 历史任务把 HTTP 200 记录为交互通过，且证据文件缺失。
3. 项目状态文档仍写“不是 Git 仓库”和旧测试数。

## 工作包

1. `WP1`：修复解析、改写、匹配、评测、LLM 和输入错误边界，并补单元测试。
2. `WP2`：重构 Web 临时目录与会话内下载数据，并补 Web 测试。
3. `WP3`：恢复虚拟环境，执行必跑传感器、运行时与交互验证。
4. `WP4`：同步 Harness、长期文档和交接记录，按边界提交。

## 影响边界

- 业务模块：`app/`、`web_app.py`、`tests/`。
- 项目状态：`.harness/`、`docs/` 和必要的项目说明文件。
- 不涉及：远端推送、生产依赖升级、同仓库兄弟项目。
