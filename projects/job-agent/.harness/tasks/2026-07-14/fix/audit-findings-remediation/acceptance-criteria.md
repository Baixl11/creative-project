# 验收标准

## 功能正确性

- `AC-01`：改写结果不把“参与”提升为“主导”，不凭空加入 G 端、0-1 或不存在的指标。
- `AC-02`：纯联系方式输入不会出现在简历 highlights；有效经历仍可被提取。
- `AC-03`：福利等忽略章节的正文不会被解析成职位要求。
- `AC-04`：AI、协作、交付、优化等概念不会跨组或重复抬高匹配度；无要求时得分为 0。
- `AC-05`：评测存在失败用例时进程返回非零状态。
- `AC-06`：LLM 网络、HTTP、JSON、结构错误均转换为项目级错误；自动降级后模式为 `mock-fallback`。
- `AC-07`：非法 UTF-8 文本返回可理解的输入错误。

## Web 与隐私

- `AC-08`：上传内容和生成文件仅存在于单次临时目录，任务结束后目录删除。
- `AC-09`：页面 rerun 后仍能从 session state 展示和下载最近一次报告，不依赖已删除路径。
- `AC-10`：下载 JSON 不暴露服务器绝对路径。

## 验证与交付

- `AC-11`：项目单元测试、评测、编译、公开 CLI 和 Harness 计划验证通过。
- `AC-12`：私有样例不存在时如实记录为无法执行，不伪造通过。
- `AC-13`：Streamlit 能启动；真实页面交互要么有浏览器证据，要么任务明确停在待确认状态。
- `AC-14`：Harness 状态、历史交互记录和长期文档与当前事实一致。
