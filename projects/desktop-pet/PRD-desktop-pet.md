# PRD: 桌面宠物 - 线条小狗 MVP

## 1. Summary

本项目要做一个可运行在 Windows 和 macOS 上的桌面宠物应用。第一版先提供一只带 3D 感的线条小狗，让用户能在桌面上拖动、点击、抚摸和简单 DIY 外观。

第一版目标不是做完整宠物平台，而是先做出一个可爱、轻量、有生命感的桌面互动 Demo。

## 3. Background

桌面宠物是一类轻陪伴产品。它的价值不在于完成复杂任务，而在于让电脑桌面更有趣、更有情绪连接。

这个项目希望做一个可以在桌面上有效互动的宠物。用户不仅能看见它，还能用鼠标和它玩。长期来看，用户可以 DIY 自己的桌面形象。第一版先从“线条小狗”切入，因为线条风格实现成本低、辨识度高，也更容易做出轻盈的 3D 感。

现在适合先做 MVP 的原因：

- 桌面端跨平台技术已经成熟，可以较快做出透明置顶窗口。
- Web 3D 技术可以较快做出线框小狗、简单动画和互动反馈。
- 用户对个性化桌面、陪伴型小组件、轻量 AI 角色有持续兴趣。
- 先验证“桌面上可互动宠物是否有吸引力”，比直接做完整 DIY 平台更稳。

## 4. Objective

### Objective

做出第一版可体验的桌面宠物应用：用户打开后，桌面上出现一只线条小狗；用户可以移动它、点击它、抚摸它，并修改一些基础外观。

### Why It Matters

对用户来说，它能让桌面更有陪伴感，也能表达个人风格。对项目来说，它能验证核心体验：桌面宠物是否足够有趣，是否值得继续扩展成多宠物和 DIY 平台。

### Key Results

| Key Result | Target |
| --- | --- |
| KR1 | Windows 和 macOS 上都能启动应用，并显示透明无边框桌面宠物窗口 |
| KR2 | 线条小狗至少支持 5 个基础状态：待机、看向鼠标、被点击、被拖动、开心 |
| KR3 | 用户能完成 4 个核心互动：拖动、点击、鼠标靠近、抚摸 |
| KR4 | 用户能修改至少 4 类外观参数：颜色、大小、线条粗细、耳朵/尾巴样式 |
| KR5 | 空闲状态下 CPU 平均占用低于 5%，内存稳定低于 300MB |
| KR6 | 冷启动后 3 秒内显示线条小狗 |
| KR7 | 新用户在 1 分钟内可以完成拖动、点击和一次 DIY 修改 |
| KR8 | 连续运行 1 小时后无明显卡顿、闪退或宠物消失 |
| KR9 | 5-10 名内测用户中，至少 60% 表示愿意让桌宠继续运行 1 天以上 |

## 5. Market Segments

### Primary Segment: 个性化桌面用户

这些用户喜欢美化桌面、使用小组件、动态壁纸、桌面插件。他们希望电脑桌面不只是工具，也能有个人风格。

他们的需求：

- 想让桌面更有趣。
- 想要轻量、不会打扰工作的陪伴。
- 想要简单自定义外观。

### Secondary Segment: 二次元/可爱风用户

这些用户喜欢虚拟形象、电子宠物、桌宠、轻互动角色。他们更看重宠物是否可爱、动作是否有生命感。

他们的需求：

- 想要角色有情绪反馈。
- 想通过点击、抚摸获得即时反馈。
- 希望未来能换宠物、换外观、导入自定义形象。

### Future Segment: 创作者和开发者

这些用户可能希望用项目做自定义桌宠、品牌 mascot、AI 助手外壳或展示 Demo。他们不是 MVP 的主要目标用户，但会影响后续扩展方向。

他们的需求：

- 希望后续支持导入模型或配置角色。
- 希望结构清晰，方便二次开发。
- 希望宠物行为和外观可以扩展。

## 6. Value Propositions

### User Jobs

- 当用户长时间使用电脑时，希望桌面有一个轻松、有趣的小陪伴。
- 当用户想个性化电脑时，希望快速放一个属于自己的桌面角色。
- 当用户感到工作枯燥时，希望通过简单互动获得一点情绪反馈。

### Gains

- 桌面更有生命感。
- 用户可以拥有一只属于自己的线条小狗。
- 不需要复杂学习，就能拖动、点击、抚摸和改外观。
- 第一版轻量，不会像大型应用一样打扰用户。

### Pains Avoided

- 不需要复杂设置。
- 不需要高性能电脑。
- 不需要先导入复杂模型。
- 不把桌宠做成遮挡工作内容的重型窗口。

### Differentiation

相比普通 2D 桌宠，本项目第一版强调 3D/线条感，让小狗更有空间感。相比完整虚拟助手，本项目先聚焦“陪伴和互动”，避免早期功能过重。

## 7. Solution

### 7.1 UX / User Flow

#### First Launch Flow

1. 用户启动应用。
2. 桌面上出现一只默认线条小狗。
3. 小狗处于待机状态，会轻微呼吸、摇尾巴或眨眼。
4. 用户移动鼠标靠近，小狗看向鼠标。
5. 用户点击小狗，小狗做开心反馈。
6. 用户拖动小狗，小狗跟随鼠标移动。

#### DIY Flow

1. 用户从托盘菜单或右键菜单打开设置。
2. 用户调整颜色、大小、线条粗细等参数。
3. 小狗实时预览变化。
4. 用户调整后自动应用并写入本地配置；如果想回到打开设置时的状态，可以点击“还原”。

#### Basic Control Flow

1. 用户右键小狗或托盘图标。
2. 菜单显示：显示/隐藏、恢复默认位置、打开设置、退出。
3. 用户选择对应操作。

#### Desktop Behavior Flow

1. 用户启动应用后，小狗默认出现在主屏幕右下角附近。
2. 用户可以拖动小狗到任意屏幕位置。
3. 应用记住小狗最后位置。
4. 如果用户切换显示器、拔掉外接屏或分辨率变化，小狗自动回到当前主屏幕可见区域。
5. 当用户进入全屏应用或游戏时，MVP 默认继续显示；全屏自动隐藏作为后续版本能力。

### 7.1.1 Desktop Window Behavior

桌面窗口是这个产品的核心体验。第一版需要明确窗口行为，避免小狗干扰用户正常使用电脑。

| Behavior | MVP Decision |
| --- | --- |
| 默认层级 | 默认置顶，保证用户能看到小狗 |
| 透明窗口 | 背景透明，只显示宠物和必要交互区域 |
| 无边框 | 不显示系统窗口标题栏和边框 |
| 拖动方式 | 鼠标按住宠物主体拖动 |
| 位置记忆 | 记住上次关闭前的位置 |
| 多显示器 | 默认出现在主屏幕；拖到副屏后记录副屏位置 |
| 屏幕变化 | 如果记录位置不可见，自动回到主屏幕右下角 |
| 点击穿透 | MVP 不实现，仅预留技术设计；V0.2 提供开关 |
| 全屏应用 | MVP 默认继续显示；V0.2 增加“全屏时隐藏”开关 |
| 设置面板 | MVP 使用普通设置窗口，从托盘菜单或宠物右键菜单打开 |
| 退出行为 | 用户选择退出后完全关闭进程 |

### 7.1.2 Interaction Rules

互动规则需要清楚，方便工程实现状态机。

| Interaction | Trigger | Response | Notes |
| --- | --- | --- | --- |
| Hover | 鼠标进入宠物互动区域 | 小狗看向鼠标，尾巴轻微摆动 | 鼠标离开 1 秒后回到 Idle |
| Click | 鼠标左键点击宠物主体 | 播放开心或惊喜动画 | 点击反馈冷却 500ms，避免连续触发过快 |
| Drag | 鼠标按住宠物主体并移动 | 小狗跟随鼠标移动 | 拖动时暂停 Hover 和 Click 动画 |
| Petting | 鼠标在宠物主体区域内连续移动 600ms 以上 | 小狗进入 Happy 状态 | 需要鼠标移动轨迹，不只是静止悬停 |
| Right Click | 右键宠物主体 | 打开快捷菜单 | 不触发开心动画 |

State Priority:

1. Dragging
2. Right-click menu open
3. Petting / Happy
4. Clicked
5. Hover
6. Idle

Pointer Event Rules:

- 只有小狗主体互动区域接收鼠标事件。
- 透明背景不响应鼠标事件，也不应该挡住用户操作桌面。
- MVP 不支持宠物主体点击穿透；透明区域不拦截鼠标不等于宠物主体点击穿透。
- 宠物主体互动区域可以略大于可见线条，避免用户难以点中。
- 右键菜单打开时，暂停 Hover、Click 和 Petting 状态切换。

### 7.1.3 Visual Style Requirements

第一版视觉应保持轻量、清晰、可爱，不追求复杂写实。

| Item | Requirement |
| --- | --- |
| Base style | 极简线条小狗，MVP 默认黑白线框；彩色线条作为 DIY 选项 |
| 3D feel | 通过线框结构、轻微透视、头部转向和尾巴摆动体现 |
| Default size | 桌面默认占用约 160px-220px 宽度 |
| Line width | 默认 2px-4px，DIY 中可调整 |
| Color | 默认黑白高对比线条，彩色线条通过 DIY 修改 |
| Facial expression | 至少支持默认眼睛和开心眼睛 |
| Animation tone | 动作轻快，不做大幅闪烁或强干扰动效 |
| Background | 不显示背景卡片，不遮挡桌面 |
| Accessibility | 在浅色和深色桌面背景上都应可见 |

### 7.1.4 DIY Settings Specification

MVP 的 DIY 不做复杂编辑器，只提供低成本、高感知的外观参数。

| Setting | Type | MVP Options |
| --- | --- | --- |
| 线条颜色 | Color picker + presets | 白色、黑色、蓝色、粉色、绿色、自定义 |
| 宠物大小 | Slider | 80%-140% |
| 线条粗细 | Slider or segmented control | 细、默认、粗 |
| 耳朵样式 | Segmented control | 垂耳、立耳 |
| 尾巴样式 | Segmented control | 短尾、卷尾 |
| 动画强度 | Segmented control | 安静、默认、活泼 |
| 恢复默认 | Button | 恢复所有外观和位置设置 |

DIY Acceptance Criteria:

- 修改后可以实时预览。
- 设置变更采用自动应用模型：用户调整宠物、颜色、大小、线条、耳朵、尾巴或动作强度后，短暂延迟内自动写入本地配置并同步到桌面宠物。
- 设置面板不提供“保存/取消”主流程，也不要求用户点击“应用”才能生效。
- “还原”按钮恢复到本次打开设置面板时的宠物和外观状态，并再次自动写入本地配置。
- 关闭设置面板不会额外回滚已自动应用的修改；如果用户想撤销，需要在关闭前点击“还原”。
- 如果用户调整后立刻关闭设置面板，应用需要在关闭前刷新最后一次待自动应用的修改。
- 关闭应用再打开后配置仍然生效。
- 恢复默认不会删除应用本身或其他本地文件。

### 7.2 Key Features

#### F1. Transparent Desktop Window

应用需要创建一个透明、无边框、置顶的桌面窗口。窗口只显示宠物，不显示普通应用边框。

Acceptance Criteria:

- 窗口背景透明。
- 默认置顶显示。
- 可以拖动宠物位置。
- 支持 Windows 和 macOS。
- 关闭应用后不会残留进程。
- 支持位置记忆。
- 多显示器变化后，小狗不会停留在不可见区域。

#### F2. Line Dog Pet

第一只宠物是线条小狗。MVP 优先使用 Three.js 线框/几何体实现轻量 3D，不能只是静态图片。如果性能或透明窗口兼容性不达标，可以降级为 Canvas/SVG 伪 3D，但需要保留转头、摇尾巴和状态动画。

Acceptance Criteria:

- 小狗由线条、线框或极简几何体组成。
- 能看出头、身体、耳朵、尾巴、四肢。
- 支持待机动画。
- 支持简单表情变化。
- 在不同大小下仍然清晰。
- 如果从 Three.js 降级为 Canvas/SVG，仍需满足互动和动画验收标准。

#### F3. Mouse Interaction

用户可以通过鼠标和小狗互动。

Acceptance Criteria:

- 鼠标靠近时，小狗头部或眼睛看向鼠标。
- 点击小狗时，小狗播放开心或惊喜动画。
- 拖动小狗时，小狗跟随鼠标移动。
- 鼠标连续滑过小狗身体时，可以触发抚摸反馈。
- 拖动状态优先级最高，不被其他动画打断。
- 鼠标离开宠物后，小狗在 1 秒内回到待机状态。

#### F4. Basic DIY

用户可以调整基础外观。

Acceptance Criteria:

- 支持修改线条颜色。
- 支持修改小狗大小。
- 支持修改线条粗细。
- 支持至少一种耳朵或尾巴样式切换。
- 配置保存到本地。
- 修改时可以实时预览。
- 支持恢复默认外观和默认位置。
- 设置修改自动应用，不依赖保存按钮。
- 支持“还原”到打开设置面板时的状态；关闭设置面板不会自动撤销已自动应用的修改。

#### F5. Tray / Menu Controls

应用需要提供基础控制入口。

Acceptance Criteria:

- 系统托盘可见。
- 托盘菜单包含显示/隐藏、设置、恢复位置、退出。
- 右键宠物时可打开快捷菜单。
- 设置面板使用普通窗口，可以从托盘菜单或右键菜单打开和关闭。

#### F6. State System

小狗需要有最基础的状态系统，避免所有动作互相冲突。

Initial States:

- Idle: 待机
- Hover: 鼠标靠近
- Clicked: 被点击
- Dragging: 被拖动
- Happy: 开心

Acceptance Criteria:

- 每个状态有明确动画或视觉反馈。
- 状态之间可以平滑切换。
- 拖动状态优先级高于其他状态。
- 连续快速点击、拖动和抚摸时不会出现状态卡死。

#### F7. First-Run and Recovery

应用需要处理首次启动和异常恢复场景。

Acceptance Criteria:

- 首次启动显示默认小狗。
- 如果本地配置损坏，应用使用默认配置启动。
- 如果记录的位置超出当前屏幕，自动恢复到主屏幕右下角。
- 应用崩溃重启后不会打开多个宠物实例。

### 7.3 Technology

Recommended Stack:

- Desktop shell: Electron 或 Tauri
- UI: React 或轻量前端框架
- 3D rendering: Three.js
- Storage: 本地 JSON 配置或浏览器 localStorage
- Packaging: electron-builder 或 Tauri bundler

Initial Recommendation:

第一版建议使用 Electron + React + Three.js。原因是开发效率高，透明窗口、托盘、跨平台打包和 Web 3D 生态都比较成熟。

后续如果包体积或性能成为关键问题，再评估迁移到 Tauri。

### 7.3.1 Performance and Compatibility

| Area | MVP Target |
| --- | --- |
| Cold startup | 冷启动后 3 秒内显示宠物 |
| Idle CPU | 空闲状态 5 分钟平均 CPU 占用低于 5% |
| Memory | 连续运行 1 小时后内存稳定低于 300MB，且无持续增长趋势 |
| Frame rate | 默认动画目标 30 FPS；需要时可降低动画强度 |
| Windows | 优先支持 Windows 10/11 |
| macOS | 优先支持 macOS 13 及以上 |
| Offline | MVP 完全离线可用 |

### 7.3.2 Privacy and Local Data

MVP 不需要账号、云同步或远程数据采集。

Local Data:

- 宠物位置。
- DIY 外观配置。
- 应用基础设置。

Privacy Requirements:

- 默认不采集用户桌面内容。
- 默认不上传任何本地配置。
- 如果未来加入 AI 对话、云同步或数据分析，需要单独更新 PRD 和隐私说明。

### 7.4 Assumptions

| Assumption | Risk | Validation |
| --- | --- | --- |
| 用户会喜欢线条小狗风格 | Medium | 做可运行 Demo，收集反馈 |
| 3D/线框表现能带来明显差异 | Medium | 对比 2D 静态版本和 3D 版本 |
| Electron 性能足够 | Medium | 测试空闲 CPU/GPU 占用 |
| 简单 DIY 已足够支撑第一版 | Low | 观察用户是否要求导入模型或换装 |

| 用户不会认为置顶宠物打扰工作 | Medium | MVP 提供隐藏和恢复位置；V0.2 评估点击穿透和全屏隐藏 |
| 线条小狗能在不同桌面背景上保持可见 | Medium | 在浅色、深色、复杂壁纸上做视觉测试 |

## 8. Release

### MVP Scope

第一版包含：

- 跨平台桌面应用基础框架。
- 透明无边框置顶窗口。
- 第一只宠物：线条小狗。
- 待机、看鼠标、点击、拖动、开心反馈。
- 基础 DIY：颜色、大小、线条粗细、耳朵/尾巴样式。
- 托盘菜单：显示/隐藏、设置、恢复位置、退出。
- 本地保存配置。
- 多显示器和屏幕变化的基础恢复逻辑。
- 完全离线使用，不需要账号。
- 提供内部测试用可执行包或安装包，不做应用商店发布。

### Out of Scope for MVP

第一版不包含：

- AI 对话。
- 多宠物系统。
- 完整 3D 建模编辑器。
- 用户导入复杂模型。
- 复杂物理碰撞。
- 云同步。
- 应用商店发布。
- 语音互动。
- 宠物成长系统。
- 点击穿透开关。
- 全屏应用自动隐藏。
- 开机自启动。

### MVP Acceptance Checklist

#### Windows

- 应用可启动，并在桌面显示透明小狗窗口。
- 小狗可以拖动、点击、抚摸。
- 托盘菜单可用。
- 设置保存后重启仍生效。
- 设置可还原到打开设置面板时的外观；关闭设置面板不会自动撤销已自动应用的修改。
- 退出后进程关闭。
- 重复启动应用时不会出现多个宠物实例。
- 本地配置损坏时可以用默认配置恢复启动。

#### macOS

- 应用可启动，并在桌面显示透明小狗窗口。
- 小狗可以拖动、点击、抚摸。
- Dock/菜单栏表现符合预期。
- 设置保存后重启仍生效。
- 设置可还原到打开设置面板时的外观；关闭设置面板不会自动撤销已自动应用的修改。
- 退出后进程关闭。
- 重复启动应用时不会出现多个宠物实例。
- 本地配置损坏时可以用默认配置恢复启动。

#### Cross-platform

- 默认位置不遮挡主要工作区域。
- 多显示器变化后宠物仍可见。
- 连续运行 1 小时无明显卡顿或崩溃。
- 浅色、深色和复杂壁纸下线条小狗都可见。
- 空闲状态 5 分钟平均 CPU 占用低于 5%。
- 连续运行 1 小时后内存稳定低于 300MB。
- 鼠标事件只由宠物主体互动区域接收，透明背景不挡住桌面操作。

## Resolved MVP Decisions

1. MVP 默认视觉为黑白高对比线条小狗，彩色线条作为 DIY 选项。
2. MVP 不做宠物主体点击穿透，不做全屏应用自动隐藏；两者放到 V0.2。
3. MVP 设置面板使用普通窗口，从托盘菜单或宠物右键菜单打开。
4. MVP 设置采用“自动应用 + 还原”，不采用“保存 + 取消”。
5. MVP 不做开机自启动；该能力放到 V0.2。
6. MVP 提供内部测试用可执行包或安装包，不做应用商店发布。
