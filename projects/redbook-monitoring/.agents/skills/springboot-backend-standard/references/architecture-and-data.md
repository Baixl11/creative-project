# Spring Boot 架构与数据检查

## 模块边界

- 为每个模块定义公开 API、数据 Owner 和允许依赖方向。
- 跨模块读取不直接复用对方 Entity/Repository；使用公开 service、查询接口或事件。
- 用架构测试或构建模块约束防止反向依赖和内部包泄漏。
- 只有独立部署、扩缩、故障和团队边界成立时才拆微服务。

## HTTP 与序列化

- DTO 明确输入、输出和版本，不依赖 Entity 默认序列化。
- 验证错误、业务冲突、未认证、无权限和不存在具有稳定机器语义。
- 时间、金额、分页、排序和枚举在 OpenAPI 与实际 JSON 中一致。
- 文件、流、SSE、异步任务和 204 响应不套破坏协议的 envelope。

## JPA/MyBatis

### JPA

- 明确聚合边界、fetch plan、cascade 和 orphan removal。
- 避免开放会话掩盖 lazy load；在事务内完成所需读取并映射 DTO。
- 检查 N+1、笛卡尔积、批量写入和分页 fetch join。

### MyBatis

- SQL 参数化，动态片段使用受控枚举或白名单。
- ResultMap、分页、批处理和事务归属明确。
- 复杂 SQL 使用真实数据库集成测试，不只测试 mapper mock。

## 事务与一致性

- 记录事务的起点、资源、隔离级别、超时和失败语义。
- 对并发写入使用唯一约束、version、条件更新或锁。
- 事件发布与数据库提交使用 outbox 或可证明的等价机制。
- 消费者使用业务幂等键，处理重复、乱序、延迟和死信。

## 迁移

1. 确认项目只使用一个主要迁移工具。
2. 在目标数据库方言和数据规模下测试 migration。
3. 大表 DDL、索引和 backfill 评估锁、磁盘和时长。
4. 混合版本部署期间保持 schema 与消息兼容。
5. 删除旧字段前用指标确认旧代码和消费者已退出。
