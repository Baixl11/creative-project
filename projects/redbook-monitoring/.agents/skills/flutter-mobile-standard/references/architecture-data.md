# Flutter Architecture And Data

## 状态与依赖边界

- 先使用 Widget 本地状态处理短生命周期交互；跨页面、可恢复或业务一致性状态才进入选定的状态管理层。
- 按一致性边界拆分 provider/bloc/store，不以“每模块只能一个”制造巨型状态对象。
- 将副作用、网络和存储放在 repository/data source；状态层编排用例，Widget 展示状态和发出意图。
- 为订阅、stream、controller 和异步任务定义 dispose/cancel；防止页面离开后写状态。
- 不混用 Riverpod、Bloc 和 Provider 来实现同一所有权；迁移期间明确旧/新边界和退出条件。

## 模型与运行时边界

- 将 API DTO、持久化实体、领域模型和 UI 模型按需要分离；以 mapper 保持关系，不追求一个类型覆盖所有层。
- 在 JSON 边界处理缺字段、null、未知枚举、版本和格式错误；生成代码也要有失败测试。
- 对 money、时间、时区、locale、ID 和分页建立明确表示，避免依赖隐式字符串约定。
- 代码生成文件由项目既有策略提交或在 CI 生成；CI 检查生成结果没有漂移。
- fixture/mock 从契约或 builder 产生，覆盖旧版本和非法数据，不把开发 mock 打进生产行为。

## 远端、缓存与离线同步

- 标明哪个后端或本地实体是权威源，以及缓存命中、过期、刷新和清除策略。
- 离线读取区分 fresh、stale、syncing、failed/conflict，不能把旧数据默认为最新成功。
- 离线写入使用稳定操作 ID/幂等键，持久化队列并定义重放顺序、依赖、取消和失败上限。
- 冲突策略按业务选择 server-wins、client-wins、字段合并或人工处理，并保留版本/etag/更新时间依据。
- 数据库 migration 在事务、备份和回滚条件下测试；不可逆迁移要兼容上一版应用或采用阶段迁移。

## 网络可靠性

- 设置连接和响应超时、请求取消、统一错误分类以及日志脱敏。
- 只重试 GET/HEAD 等幂等请求，或带服务端认可幂等键的写请求；认证失败、校验失败不得盲目重试。
- 使用指数退避和随机抖动，限制次数与总时长；App 进入后台或用户取消时停止无意义重试。
- 连接状态只作为提示，不代表服务可达；以真实请求结果驱动 UI。
- 防止重复提交和请求竞态；旧响应不得覆盖较新的筛选、会话或编辑结果。

## 权限、机密与隐私

- 权限在功能即将使用时申请，先说明用途；覆盖 denied、permanently denied、restricted 和设置页返回。
- 同步维护 Android manifest/SDK 行为和 iOS plist/entitlements/privacy 描述；只声明实际使用能力。
- preferences、普通数据库和日志不得保存访问令牌、密钥或敏感个人数据；使用平台安全存储并设计注销清除。
- 截图、剪贴板、通知、后台任务和分析 SDK 评估敏感数据暴露；按产品要求提供用户控制。
- 日志和崩溃报告过滤令牌、请求体、定位、联系人、设备标识和个人内容。

## 生命周期与平台插件

- 使用项目版本支持的生命周期 API，按数据时效、登录状态和前后台时长决定刷新。
- 后台任务适配 Android/iOS 限制，不能假设定时器持续运行；任务必须可重入、可取消和幂等。
- 平台通道输入输出做运行时校验和错误映射；原生异常不能直接泄露给 UI。
- 插件升级前验证最低系统版本、权限、原生构建、隐私清单和真实设备行为。
