# FastAPI 运行时与数据检查

## 版本与执行模型

1. 从锁文件和运行环境读取版本，不依赖记忆中的最新 API。
2. 核对 Pydantic 配置、序列化和 ORM 映射是否符合实际 major 版本。
3. 核对 SQLAlchemy/SQLModel session、engine 和驱动的同步/异步组合。
4. 使用 lifespan 管理连接池、客户端和启动资源；不要依赖不确定的模块导入副作用。
5. CPU 密集任务使用进程池、worker 或外部任务系统，不阻塞事件循环。

## Session 与事务

- 每个请求或 use case 获得明确 session 所有权。
- 在业务边界提交，在异常路径回滚并释放连接。
- 避免 repository 内部自行提交，使调用方无法形成原子事务。
- 远程调用和长时间等待通常不应占用数据库事务；需要一致性时采用 outbox、状态机或补偿。
- 对并发修改使用版本列、条件更新、锁或数据库约束，不依赖“先查后写”。

## 查询与数据模型

- 检查 N+1、无界列表、缺少索引、隐式 lazy load 和过量字段。
- 分页定义稳定排序和游标/偏移语义；总数查询按成本决定。
- 数据库约束是关键一致性的最后防线，Pydantic 校验不能替代唯一键和外键。
- 区分请求 schema、响应 schema、领域对象和 ORM 模型；允许显式映射，不要求共享一个类型。

## 迁移与兼容

| 阶段 | 要求 |
|---|---|
| Expand | 新增兼容字段、表或索引，不立即删除旧结构。 |
| Backfill | 可恢复、可观测、可重复地迁移历史数据。 |
| Switch | 应用读写切换受 feature flag、版本或发布顺序控制。 |
| Contract | 确认旧实例和消费者退出后再删除旧结构。 |

验证迁移在目标数据库方言上执行。大表操作需评估锁、时长和磁盘；提供失败恢复和回滚/前滚策略。

## API 契约变更

- 列出 HTTP 调用方、生成 SDK、webhook、后台任务和数据导出。
- 将新增可选字段、收紧验证、删除字段和语义变化区分处理。
- 对枚举新增未知值容忍策略，避免旧客户端反序列化失败。
- 记录兼容窗口、弃用信息和监控指标。
