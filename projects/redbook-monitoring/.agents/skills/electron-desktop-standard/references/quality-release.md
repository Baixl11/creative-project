# Electron Quality And Release

## 性能与可靠性

- 为冷启动、首窗可交互、空闲内存、窗口新增内存、IPC 延迟和大文件吞吐设可测预算。
- 延迟加载非首屏窗口和重型模块；不要在 `app.whenReady()` 前执行非必要 I/O。
- 使用流和背压处理大文件，限制并发、临时空间和内存；验证取消与异常恢复。
- 监控 renderer 崩溃、utility process 退出、无响应窗口、未处理异常和数据库损坏，但上传前脱敏。
- 只在测量证明有效后做缓存和 memoization；定义缓存所有者、容量、失效和清理。

## 无障碍与桌面体验

- 保留语义 HTML、可见焦点、正确标签和错误关联；所有主要流程支持键盘完成。
- 检查应用菜单、快捷键冲突、焦点在窗口/对话框间恢复以及系统关闭行为。
- 支持系统缩放、文本放大、高对比度、深浅主题、reduced motion 和屏幕阅读器。
- 在 Windows、macOS 和 Linux 分别检查系统对话框、菜单习惯、路径、权限和辅助技术差异。

## 测试矩阵

- 单元测试覆盖纯业务逻辑、路径策略、更新决策和错误映射。
- 契约测试从 runtime schema 驱动 main/preload/renderer 成功与失败用例，包括恶意 sender 和非法参数。
- 集成测试覆盖数据库迁移、原子文件操作、窗口重建、协议和离线/失败恢复。
- Playwright 或等价工具至少对打包应用执行启动、关键流程、关闭和重启持久化检查；不要只测 dev server。
- 在实际发布目标的 OS/架构 CI 或发布候选机上做 smoke test，并记录无法自动化的签名/更新验收。

## 打包与更新

- 明确采用 Forge 或 electron-builder 的一个发布所有者，固定 artifact 命名、架构和渠道。
- Windows 验证代码签名和安装/卸载；macOS 验证 hardened runtime、签名、公证和 entitlements；Linux 明确包格式和更新支持范围。
- 更新元数据和二进制必须经 TLS 与签名验证；生产版本不得接受测试 feed 或降级到未签名包。
- 支持 stable/beta 等明确渠道、分批比例、暂停开关、失败指标和回滚到最近安全版本。
- 更新前处理未保存数据和数据库兼容性；应用更新与不可逆数据迁移不要绑定成无回退的一步。
- 保存可复现的版本、source map/symbol、SBOM 或依赖清单以及已签名回滚工件。

## 发布门

发布前要求 typecheck、lint、测试、生产打包、签名验证和 packaged smoke test 全部通过。记录已知风险、人工验收、监控阈值、回滚负责人和回滚步骤；不能执行的平台必须明确标为未验证。
