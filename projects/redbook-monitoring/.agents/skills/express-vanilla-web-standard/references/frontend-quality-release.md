# 原生前端与发布参考

## 模块与状态

- 避免单个脚本同时承担 API、状态、格式化、图表、弹窗和所有页面渲染；优先提取纯函数与共享 DOM/图表模块。
- 使用 ES modules 和显式导入导出；页面入口只初始化当前页面需要的能力。
- 异步请求使用请求标识或 AbortController 防止旧响应覆盖新筛选状态。
- 自定义日期范围可存在 `sessionStorage`，新浏览器会话恢复最近 30 天默认值。

## DOM 与可访问性

- 输入必须有 `<label>` 或等价可访问名称；仅有 placeholder 不合格。
- 当前导航使用 `aria-current="page"`；切换按钮使用 `aria-pressed` 或正确 tab 语义，并与视觉状态同步。
- 弹窗使用原生 `<dialog>` 或完整实现焦点管理、Escape、初始焦点和关闭后焦点恢复。
- 可点击目标推荐至少 44x44 CSS px；全站提供清晰 `:focus-visible`。
- 图表数据点支持鼠标、键盘焦点和触摸；tooltip 包含日期、指标名、值和数据口径。

## 响应式与数据密度

- 页面级 `scrollWidth` 不得大于 `clientWidth`；只允许表格/图表等明确区域内部横向滚动。
- 移动端导航优先单行可滚动或底部导航，避免占用首屏大面积高度。
- 长时间序列保留全部数据点，通过内部滚动查看，不抽样伪装成完整数据。
- 表格包含 caption、稳定表头和空/加载/错误状态；不可用字段显示原因，不显示误导性 `0`。

## 测试与发布

- 纯函数和服务补 `node:test`；API 验证响应码、契约和安全头；数据库测试使用临时或内存 SQLite。
- Playwright 至少覆盖五类流程：页面加载、筛选切换、弹窗、后台任务状态、桌面/移动端无页面级溢出。
- CI 运行语法检查、单元测试和不依赖真实凭据的数据一致性测试；真实采集测试仅在受控本地环境运行。
- 发布前检查：无模拟数据、无敏感文件、无 raw error、迁移幂等、README 与实际调度/命令一致。
