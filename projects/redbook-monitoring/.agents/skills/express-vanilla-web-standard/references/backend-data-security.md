# 后端、数据与安全参考

## Express 边界

- 服务入口负责创建依赖、注册中间件、路由与统一错误处理；可测试逻辑放入独立模块。
- 对 JSON body 设置合理大小上限；对 ID、日期、URL、枚举和文本长度做服务端验证。
- 关闭 `X-Powered-By`，设置 CSP、`nosniff`、`frame-ancestors`/`X-Frame-Options`、Referrer Policy 与 Permissions Policy。
- 5xx 响应只返回稳定公开信息；详细异常仅进入经过脱敏的本地日志。

## SQLite

- 开启外键、WAL 和 busy timeout；每个业务事务保持短小。
- 使用 `schema_migrations` 记录顺序版本；每个迁移独立 `BEGIN IMMEDIATE`/`COMMIT`，失败回滚且不登记版本。
- 所有查询参数化；动态表名或列名只能来自代码内白名单。
- 采集写入先验证来源完整性，再在单事务内写快照、指标、笔记和审计记录。

## 多存储一致性

- SQLite 与 `.env`/session 无法共享事务时，建立服务层 Saga：记录第一步结果，第二步失败时执行明确补偿。
- 删除优先处理可恢复的一侧，并在后一侧失败时恢复前一侧快照。
- 原子文件写入流程：同目录临时文件、权限 `0600`、完整写入、rename、最终 chmod、finally 清理临时文件。

## 后台任务与日志

- 后台任务由常驻服务持有状态；浏览器仅触发、轮询和消费结果。
- 单账号失败不得阻塞其他账号；整体状态区分 success、warning、error。
- 日志保留发生时间、账号、事件类型、公开消息和审计摘要，不保留凭据、session、绝对路径、浏览器命令与堆栈。
- 数据写入后执行来源数量、存储数量、字段可用性与聚合一致性校验，再标记任务完成。
